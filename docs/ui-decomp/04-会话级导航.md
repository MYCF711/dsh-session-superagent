## 1. 先定结构：五个入口不是五种主页

| 主理鱼目标 | 官方真实机制 | 本次结论 |
|---|---|---|
| 左侧“主理鱼”全局中枢 | `main` 是 **keyed / root**；`sidebar.panellist` 是 **list / root**，二者用同一个 panel id | 注册一个全局 `main[key]` 页面和一条同名侧栏入口；不放入 Conversation，也不复制侧栏行 |
| 会话头部“本会话的主理鱼” | `conversation.session.header.utilities` 是 **list / session** | 只放入口按钮；点击打开当前 Session 的右栏工作台，不再打开旧中栏 Tab |
| 会话右栏工作台 | 先注册 tab type，再以 type 的 `id` 注册 `sidebar.right.pane.tab`；标题可选注册到 `.title` | 主理鱼拥有一个新的 page kind；`rightbar` / `rightbar.session` / DockKit chrome 仍由宿主拥有 |
| 右栏“开始”页入口 | tab definition 的 `guide` 数组贡献卡片；标准卡由 Guide 自己渲染 | 若保留开始页入口，在 definition 上声明 `guide`；不要替换整个开始页，也不要手画一张独立卡片 |
| 删除结果等跨页面反馈 | `shell.overlay` | 只承载 toast 等全局反馈，不作为全局主页或会话工作台容器 |

**不能混写的边界：**

- `main` 的 key 不是字面量 `main:conversation`；宿主以 `panelId ?? 'conversation'` 分派，见 `OFF:dsh-client-ui-layout/src/client/AppFrame.tsx:45-50`。
- `conversation.view` 是会话中栏视图环；`conversation.composer.dock` 是输入区 dock；二者都不是右栏。
- `sidebar.right.pane.tab` 按 definition 的 **`id`** 分派，而打开动作使用 definition 的 **`kind`**。两者不是同一个字段，见 `OFF:dsh-client-ui-sidebar-right/src/client/tab-registry.ts:93-139`。
- `sidebar://<kind>` 是右栏内部记账地址，调用方只传 kind，不自行拼 URL，见 `OFF:dsh-client-ui-sidebar-right/src/client/contract/seed.ts:35-47`。

## 2. 官方“自动化任务”：真实 slot 与页面

### 2.1 注册面

`ui-schedule` 同时提供全局管理页、当前 Session 的任务目录和右栏单任务详情；它们共享一个 Host catalog，而不是三份任务状态。核心证据在 `OFF:dsh-client-ui-schedule/src/client/index.ts:120-293`。

| 槽 / 服务 | 官方 key 或 id | 页面与职责 | 证据 |
|---|---|---|---|
| `main` | key=`schedules` | `TaskManagerPage`，跨 Session 的任务管理主页 | `index.ts:218-239`；`PANEL_ID` 在 `:66-68` |
| `sidebar.panellist` | id=`schedules`，order=`10` | 左侧“自动化任务”入口；只提供 label 和 `TaskManagerIcon` | `index.ts:240-246` |
| `conversation.session.header.utilities` | id=`schedule-catalog`，order=`-5` | 当前 Session 的自动化任务目录按钮 | `index.ts:260-278` |
| `sidebar.right.pane.tab` | key=`@deepseek-ai/dsh-client-ui-schedule/task` | `ScheduleTaskTab`，一个任务的右栏详情 | `index.ts:205-211` |
| `sidebar.right.pane.tab.title` | 同上 | 时钟图标 + 当前任务名 | `index.ts:212-217`；`ScheduleTaskTabTitle.tsx:28-38` |
| `conversation.chat.turnTail` | id=`schedule-created`，order=`20` | 新建任务卡，点击打开同一个右栏详情 | `index.ts:247-259` |
| `sidebar.session.row.leading` / `.hover` | `schedule-mark` / `schedule-tasks` | 会话行的任务标记与悬浮信息，不是主页 | `index.ts:279-292` |
| `shell.overlay` | id=`schedule.delete-toast` | 删除结果跨原页面保留 | `index.ts:136-149` |

右栏详情另有 definition：`id='@deepseek-ai/dsh-client-ui-schedule/task'`、`kind='scheduleTask'`、`priority='builtin'`，参数为 `{sessionId, id}`，见 `OFF:dsh-client-ui-schedule/src/client/definition.ts:13-40`。

### 2.2 全局页的真实交互

`TaskManagerPage` 不是一张静态卡片，而是列表 + 选中详情：

- 状态筛选为 **active / paused / ended / all**，搜索覆盖 prompt、关联 Session id 和任务名；见 `TaskManagerPage.tsx:53-105`、`:222-250`。
- 行是原生 button，选中后设置 `aria-expanded` / `aria-controls`，右侧复用 `TaskDetail`；见 `:291-346`。
- Escape 关闭详情，但 Menu 已消费的 Escape 和仍在显示的 Modal 不会连带关闭详情；见 `:179-195`。
- 详情关闭后焦点回原行；原行已消失则回页面标题。清理确认也处理触发器被刷新移除后的焦点，见 `:79-88`、`:115-165`。
- 全局页与右栏共享 `TaskDetail` / `useTaskDetail`、Host 编辑/运行/删除动作和 catalog 投影；共享的是**领域详情和动作**，不是把 `TaskManagerPage` 整棵塞进右栏。证据：`ScheduleTaskTab.tsx:1-13`、`:129-136` 与 `TaskDetail.tsx:83-127`、`:139-183`。

### 2.3 头部目录不是右栏工作台本身

`ScheduleCatalogAction` 的真实动线：

1. 当前 Session 未 open 时不显示；首次读取无任务时不显示，读取失败可显示重试入口，见 `ScheduleCatalogAction.tsx:44-80`。
2. 只有一条且读取完成时，点击直接打开该任务详情；多条时打开锚定目录。目录 portal 到 `document.body`，见 `:90-103`、`:110-137`。
3. 目录项打开 `scheduleTask` 右栏详情；删除留在目录行内，见 `:145-196` 与 `index.ts:269-275`。
4. Escape 关目录并把焦点还给触发按钮，见 `ScheduleCatalogAction.tsx:104-109`。

**对主理鱼的取舍：**主理鱼头部入口要打开的是“当前项目完整工作台”，不是任务挑选器，因此应采用下面 Forge 的“直接 open / reveal 右栏页面”动线；不应复制 Schedule 的时钟图标或先弹一层目录。

## 3. 官方“本会话的变更请求”：真实 slot 与页面

### 3.1 正确来源是 experimental Forge，不是 ui-deliverables

中文文案“代码审查和变更”“本会话的变更请求”位于 `OFF:dsh-experimental-client-ui-forge/src/client/locales.ts:32-33`、`:63-76`。对应实现是 `dsh-experimental-client-ui-forge`。

`dsh-client-ui-deliverables` 也注册 `sidebar.right.pane.tab`，但其 kind 是 `changes-review`，语义是“一轮 Session 产出文件的逐文件前后比较”，见 `OFF:dsh-client-ui-deliverables/src/client/review-definition.ts:1-18`。**不能把这两个页面混称为同一个“变更请求”页面。**

### 3.2 注册与打开方式

`OFF:dsh-experimental-client-ui-forge/src/client/mount.ts` 给出完整链路：

| 项 | 真值 | 证据 |
|---|---|---|
| tab type | id=`@deepseek-ai/dsh-experimental-client-ui-forge`；kind=`forge-panel` | `mount.ts:55-60` |
| 开始页卡 | definition 的 `guide`：id=`review`、order=`15`、标题“代码审查和变更”、分支图标 | `mount.ts:351-356` |
| 右栏正文 | `sidebar.right.pane.tab[key=TAB_ID]` → `ForgeTab` | `mount.ts:357-359` |
| 右栏标题 | `sidebar.right.pane.tab.title[key=TAB_ID]` → `ForgeTabTitle` | `mount.ts:360-362`；`ForgeTabTitle.tsx:14-20` |
| 头部入口 | `conversation.session.header.utilities[id=forge-panel]`，order=`-8` | `mount.ts:370-388` |
| 变更详情 | 另一个 changes tab type + 同 id 的 body/title；由 `tab.actions.openResource(...)` 打开 | `mount.ts:363-369`；`ForgeTab.tsx:191-203` |

Forge 头部按钮是**显示 / 隐藏同一个右栏页**：

- 仅在有绑定变更请求、目录是已知 Git checkout，或检查失败等真实状态下出现；见 `HeaderButton.tsx:27-51`。
- 按钮使用 `aria-pressed`，有需处理项时增加错误 StateDot；见 `:47-66`。
- 未显示时 `ctx.sidebarRight.openTab('forge-panel')`；已显示时找到当前 Session 的该 kind tab 并 `hide(tab.id)`，见 `mount.ts:376-385`。

`ForgeTab` 本体显示 checkout、可刷新的本地变更和“本会话的变更请求”列表；空态、断线重连、卡片展开/收起和进入变更详情都在同一 Session 页面内完成，见 `ForgeTab.tsx:159-263`。这说明主理鱼的 watcher / Ticket / Outbox / 草稿可以同处一个 Session page，不必为每个领域对象新造中栏 Tab。

## 4. 右栏“开始”页与标准入口卡

### 4.1 开始页自己也是普通 tab type

- kind=`guide`，id=`@deepseek-ai/dsh-client-ui-sidebar-right/guide`，标题“开始”，见 `OFF:dsh-client-ui-sidebar-right/src/client/tabs/guide/definition.ts:8-26` 和 `contract/seed.ts:35-36`。
- 空右栏的播种规则：只有一个 guide entry 时直接播那个页面；零个或多个时播 Guide，见 `contract/seed.ts:21-32`。
- 宿主把 Guide 的 body/title 也注册进同一对 keyed slot；不是另写一套开始页壳，见 `OFF:dsh-client-ui-sidebar-right/src/client/index.ts:290-308`。

### 4.2 卡片动线与扩展边界

- definition 的 `guide[]` 提供 `id/order/title/description/icon/commandId`；缺图标时官方回退 CubeGlyph，见 `tab-registry.ts:61-90`。
- 标准入口是原生 button，可带 `aria-keyshortcuts` 和真实 ShortcutKeys；不超过四张可见卡时显示 description，超过则省略描述，见 `GuideBody.tsx:61-91`、`:142-159`。
- 选卡后执行 `tab.actions.openTab(kind, {replaceTab:true})`，再关闭 Guide；已有页面会被 reveal，见 `GuideBody.tsx:128-141`。
- `sidebar.right.tab.guide.entry` 只用于**按 provider id 自定义某张卡的渲染**；普通标准卡不需要注册它。`sidebar.right.tab.guide` 是替换整棵 Guide 的 chain，主理鱼不应使用，见 `contract/slots.ts:79-99` 和 `GuideBody.tsx:1-19`、`:128-177`。
- tab strip 的“添加”通过 `openTab('guide', …)` 打开开始页；全屏、收起等 chrome 由宿主持有，见 `SidebarRight.tsx:171-190`、`:272-305`、`:338-372`。

## 5. 已证实的 API 形状（官方示例，不是主理鱼现状）

以下只摘录导航字段，证明调用形状；业务 inject/store/locale 仍需按真实组件补齐。

### 5.1 全局页与左栏入口

```ts
const PANEL_ID = 'schedules' as MainPanelId

ctx.slots.inject('main', () => ctx.slots.register({
  name: 'main',
  key: PANEL_ID,
}, TaskManagerPage))

ctx.slots.inject('sidebar.panellist', () => ctx.slots.register({
  name: 'sidebar.panellist',
  id: PANEL_ID,
  order: 10,
  label: () => t('panel'),
}, TaskManagerIcon))
```

来源：`ui-schedule/src/client/index.ts:218-246`。侧栏读取每条注册的 `id/order/label`，点击后调用 `ctx.layout.selectPanel(id)`；图标组件本身不承担导航，见 `OFF:dsh-client-ui-sidebar/src/client/index.ts:56-85` 和 `SidebarRoot.tsx:72-100`。

`ctx.layout.selectPanel(panelId)` 只切换全局主面板，不改变当前 Session；传入未注册 key 会抛错，传 `null` 回 Conversation，见 `OFF:dsh-client-ui-layout/src/client/service.ts:27-41`、`:71-78`。

### 5.2 注册右栏 page type、正文与标题

```ts
ctx.effect(() => ctx.sidebarRightTabs.register({
  id: TAB_ID,
  kind: TAB_KIND,
  title: () => t('tab.title'),
  guide: [{
    id: 'review',
    order: 15,
    title: () => t('guide.title'),
    description: () => t('guide.description'),
    icon: IconBranchOutlineRegular,
  }],
}), 'forge-panel: sidebar tab')

ctx.slots.inject('sidebar.right.pane.tab', () => ctx.slots.register({
  name: 'sidebar.right.pane.tab',
  key: TAB_ID,
}, ForgeTab))

ctx.slots.inject('sidebar.right.pane.tab.title', () => ctx.slots.register({
  name: 'sidebar.right.pane.tab.title',
  key: TAB_ID,
}, ForgeTabTitle))
```

来源：`ui-forge/src/client/mount.ts:351-362`。主理鱼应复用这套**注册顺序和 id/kind 关系**，不是复用 Forge 的名字、图标或业务数据。

### 5.3 从头部长 utilities 打开右栏

```ts
// 一个无额外导航参数的 Session page：Forge 的真实打开方式。
ctx.sidebarRight.openTab('forge-panel')

// 一个由 Session + task id 定位的详情页：Schedule 的真实打开方式。
ctx.sidebarRight.openTab('scheduleTask', { params: { sessionId, id } })
```

来源：`ui-forge/src/client/mount.ts:380-385`、`ui-schedule/src/client/index.ts:269-275`。

主理鱼整页工作台只需当前 Session 时，右栏 slot 本身已提供 `sessionId`；是否需要 watcher/Ticket 详情导航参数，应由实际详情动线决定，不能预造一组参数。页面 type 默认同 pane 同 kind 去重；需要独立多份时才声明 `multiple`，见 `tab-registry.ts:93-108`。

## 6. 主理鱼共享组件边界

设计中的 `SuperagentPage scope='global'|'session'` 是**待实现的组合层**，不是当前已有组件，也不是官方导出 API。落地时保持四层分离：

| 层 | 全局页 | 会话右栏 | 必须共享的事实 |
|---|---|---|---|
| 宿主容器 | `main[key]` + `sidebar.panellist[id]` | tab definition + keyed body/title + header utility | slot、生命周期、焦点和右栏几何归宿主 |
| scope 适配 | 显式读取全局投影 | 使用 slot 给出的当前 `sessionId` | 服务端过滤与跨会话写保护，不能靠前端隐藏 |
| 领域页面 | `SuperagentPage(scope='global')` | `SuperagentPage(scope='session', sessionId=…)` | 同一 watcher/Ticket/执行/Outbox/草稿/健康语义 |
| 交互组件 | 表格、编辑器、详情、确认、toast | 同一套组件 | 相同动作、busy、错误回读、键盘和焦点归还 |

官方依据是 Schedule 的“容器不同、领域详情相同”：`TaskManagerPage` 与 `ScheduleTaskTab` 都组合 `TaskDetail` / `useTaskDetail`。主理鱼可以采用一个 `SuperagentPage` 组合层，但**不能把 global/session 写成两套投影，也不能把 `ZhuliPanel` 原样复制到第三个容器。**

当前服务端 `GET /session-superagent/state?sessionId=…` 仍未真正按 Session 过滤；这是 [设计文档](../设计-会话级导航与运行时.md) §3.1 已记录的现状。导航接槽不等于数据隔离完成。

## 7. 图标、键盘与焦点

### 7.1 图标边界

- 自动化任务的全局行、头部按钮和详情标题都使用官方 `IconClockOutlineRegular`，证据：`TaskManagerIcon.tsx:1-16`、`ScheduleCatalogAction.tsx:110-129`、`ScheduleTaskTabTitle.tsx:28-38`。**主理鱼不得借这个时钟图标冒充自身入口。**
- Forge 的分支/变更请求图形只属于 Forge；开始页标准卡可声明自己的 icon，缺省才由 CubeGlyph 补位。
- 主理鱼现有 `OrbitMark` 是 16×16、带真实 watcher 状态的 derived SVG，见当前 `client.js:2231-2283`；它不是官方同构素材。头部入口可否直接复用其静态形态、如何只喂当前 Session 状态，仍需实现时核实，不能拿 Forge/Schedule 图标代替决定。
- 右栏展开按钮由宿主注册在 `conversation.session.header.corner`，使用镜像的 `IconPanelLeftOutlineRegular`；主理鱼不要再注册一个右栏开关，见 `ExpandButton.tsx:1-16`、`:34-54`。

### 7.2 已有键盘事实

- Schedule 目录：Escape 关闭并回焦触发器；TaskManagerPage：Escape 关闭详情且尊重 Menu/Modal 已消费事件。
- 右栏已有宿主命令：`sidebar.right.toggle`、`pane.split`、`pane.fullscreen.toggle`、`page.close`、`page.refresh`；绑定按 desktop/web 分开，见 `OFF:dsh-client-ui-sidebar-right/src/client/shortcuts.ts:17-99`。主理鱼不应另写一组同名快捷键。
- Guide 标准卡、Forge 头部按钮、Schedule 列表项均为原生 button；Menu 是否自动聚焦由 `autoFocus` 显式控制，例如 `GuideBody.tsx:99-115`、`TaskManagerPage.tsx:206-218`。
- **未核实**：DockKit tab strip 的方向键/Home/End 完整行为不在本次源码阅读范围内；不得凭“原生 button”写成整套 tab 键盘已通过。

### 7.3 已有焦点事实

- 右栏 open/split 后在 DOM commit 时聚焦可见 pane；关闭当前焦点所在页后把焦点交给仍存活的可见 pane，见 `close-focus.ts:7-35`。
- 宿主监听右栏 DOM 替换，尽量按 Session/pane/occurrence 延续焦点并保留选择，见 `focus.ts:68-137`；这些能力在 `index.ts:134-135`、`:195-198` 接入。
- 主理鱼自己的 Modal、编辑器和确认层仍需保证焦点回触发者；触发者因刷新消失时，采用 Schedule 的“当前控件 → 页面标题”回退，不允许掉到 `document.body` 后无人处理。

## 8. 旧中栏退出路线与当前事实

当前 `client.js` 的 `inject` 只有 `slots`，实际只注册两处：

1. `conversation.view[id=session-superagent-desk]`，order=`30`，组件 `ZhuliPanel`，见 `client.js:5303-5348`；
2. `conversation.composer.dock[id=session-superagent-orbit]`，order=`-10`，组件 `StatusOrbit`，见 `client.js:5394-5408`。

`StatusOrbit` 目前点击是切换自己的弹层，不是右栏导航，见 `client.js:2378-2388`、`:2495-2518`。当前代码中**没有** `main`、`sidebar.panellist`、`sidebarRightTabs`、`sidebarRight.openTab` 或 `conversation.session.header.utilities` 注册。

按已批准设计，迁移顺序固定为：

1. 新增左侧全局页、会话 header utility、右栏 page type/body/title；开始页卡若保留，只通过该 type 的 `guide` 声明。
2. 迁移期让旧 `conversation.view` 入口跳到已注册的全局 panel；官方可用动作是 `ctx.layout.selectPanel(panelId)`，但当前插件尚未注入 `layout`，这部分是**待实现**，不是现有能力。
3. Dock/Orbit 改为打开当前 Session 右栏，不再默认打开旧中栏或全局中栏；保留已有写确认和错误回读。
4. 两会话数据隔离、全局显式读取、导航/键盘/焦点/双主题/窄屏验收后，才删除旧中栏注册；不长期维护三个主页。
