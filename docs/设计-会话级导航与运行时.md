# 会话级主理鱼导航与运行时设计（实验仓）

状态：**已批准方向，实施中；不得写成已完成或可替代正式版。**

## 1. 产品结论

### 1.1 项目会话即 Lead

按当前 GOkifu 使用方式，一个长期会话专管一个项目。该会话已经持有项目上下文、历史决策、仓库约定和用户关系，因此由它兼任主理鱼 Lead 比另起一个 Router 更自然。

```text
一个项目会话 = 项目 Lead
简单任务 → 当前会话 inline 处理
需要隔离的任务 → 按 Ticket 创建 worker
```

独立 Runtime 与独立 Router 是两回事：轮询、状态、Ticket 和 Outbox 必须独立可靠运行，但不要求再养一个专职主 Session。

### 1.2 官方原型吸收边界

官方 `deepseek-ai/dsh-superagent-prototype@8c32a9d` 是独立 DSH bundle/profile：独立 stateDir、专用账号、Router/Worker 预设和管理页面。它适合团队协作与无人值守，不是单用户项目会话制必须照搬的部署形态。

只吸收以下骨架：

- `src/index.ts` 很薄，`Runtime` 是唯一组合根与生命周期所有者。
- `Engine` 提供单事务入口，核心依赖通过端口注入。
- `Passes` 统一持有定时器与关闭语义。
- Source、Executor、Outbox、投影和健康各有明确边界。
- Ticket 级执行隔离，而不是“一仓库一个永久专员”。

不搬：飞书、多人授权、团队角色、独立 Router 部署、重型 Eval/Settings 体系。独立 SQLite 也不是当前前置条件；先统一 Store/事务契约，再决定存储实现。

### 1.3 先顶层优雅，再房间优雅

房间数量不是目标。顶层必须先保证：

1. 组合根唯一，工具/路由只是适配层。
2. 每个领域事件只有一个事务边界，Ticket、watcher、obs 与 Outbox 不各自绕过总装写状态。
3. 定时器由调度器统一创建、停止和恢复，不允许入口散写 `state.watchers[id]`。
4. 投影只有一个事实源，client 不另维护一套 enabled/poll/健康判据。
5. 旧 watcher 与新 modular runtime 有明确退出路线，不能永久双编排。

## 2. 导航结论：全局左栏 + 会话右栏

### 2.1 左侧插件页（全局中枢）

位置：左侧导航 → 插件 → 主理鱼，对齐官方“自动化任务”的独立 `main` 页面与侧栏注册，不再把中栏对话 Tab 当管理主页。

职责：

- 全部项目会话的 watcher、Ticket、执行、Outbox 和健康。
- 已开启 / 已暂停 / 异常 / 全部筛选，搜索仓库、会话和 Ticket。
- 新建 watcher、全局凭证、Source、默认配置与健康诊断。
- 可进入任一项目会话的右栏工作台。

### 2.2 会话右栏（当前项目工作台）

入口：会话头部工具区 `conversation.session.header.utilities`，图标沿用现有主理鱼素材，提示“本会话的主理鱼”。不借用自动化任务的时钟图标。

容器：官方右侧栏页面，对齐“自动化任务目录”和“本会话的变更请求”，不新建中栏 Tab 或漂移弹层。

职责：

- 仅当前 `sessionId` 的 watcher、Ticket、执行、草稿与 Outbox。
- 修改目标、过滤条件、轮询间隔、执行方式。
- 暂停 / 恢复 / 编辑 / 删除，保留写确认、错误回读和焦点归还。
- 打开当前项目会话或对应 worker。

### 2.3 中栏退出路线

1. 先完成左侧全局页和会话右栏。
2. 旧中栏入口暂时跳转到左侧全局页，避免用户丢失入口。
3. 导航、动作和兼容性验收后移除旧中栏主理鱼 Tab，不长期维护三个主页。

### 2.4 共享视图而非复制页面

只实现一个 `SuperagentPage` 及共享表格、编辑器、详情、确认框和动作：

```text
SuperagentPage scope="global"
SuperagentPage scope="session" sessionId="当前会话"
```

容器和筛选范围不同，领域动作与错误语义相同。Dock/Orbit 点击也进入当前会话右栏，不再默认打开全局中栏。

## 3. 数据与权限契约

### 3.1 服务端 scope 是硬门槛

现状：`GET /session-superagent/state?sessionId=...` 仍从 `allWatchers` 生成完整列表，没有真正按会话过滤。只在前端隐藏其他会话不算完成。

必须实现：

- 全局页仅在明确全局入口读取全量。
- 会话页的服务端响应只含目标 `sessionId` 的 watcher/Ticket/Outbox/事件。
- 编辑、暂停、恢复、删除、flush 等写操作校验目标对象属于当前会话，禁止跨会话 ID 直接修改。
- 无 `sessionId` 时不泄露其他会话 goal、草稿或敏感执行细节。
- 会话 scope 与全局 scope 使用同一投影，禁止两套字段和 enabled/poll 语义。

### 3.2 项目绑定与重连

- 稳定身份是 `projectKey`；`sessionId` 是可重新绑定的投递地址。
- 会话休眠、宿主重启有宽限和自动重连；不得立即写 `lastError` 并退避。
- 会话确实删除时进入 `paused / waiting-rebind`，允许重新指定项目会话，不丢 watcher、Ticket 和 Outbox。
- 默认 inline 复用项目上下文；仅在需要权限/工作区隔离时创建 worker。

## 4. 运行时可靠性要求

- headless 无 `webServer` 时 enabled 守仍能启动和恢复 interval。
- 单守挂载失败不连累其他守，错误含时间并真实落盘，禁止空 catch 让故障消失。
- `nextAt` 退避、`activeHours`、`deferReason` 是正常等待，不得误报 `stalled`。
- 新守首轮有豁免；老守 + 刚启动的新进程也有启动豁免，超过阈值才报 boot-miss。
- `session-missing` 宽限期必须进入健康等待，不可一边宽限一边亮红。
- `enabled: false / 0 / "false" / "0" / "no" / "off"` 在调度器、`watch_status`、`/state` 和 client 中同义。
- 停摆守必须进入异常/问题筛选、“需要关注”、Orbit 与按仓库错误点。

## 6. 验收清单

- 结构：左侧全局页、会话右栏、旧入口迁移符合官方 slot，无新增自造主页。
- 数据：两会话隔离，全局仅显式入口可见；跨会话写操作返回 403/409，且不改变状态。
- 行为：新建、编辑、暂停、恢复、删除、Ticket/Outbox/草稿、Session 导航全部走真实 API。
- 可访问性：双主题、窄屏、键盘、焦点归还、错误/空态/加载态通过。
- 稳定性：headless 启停、会话休眠/重连、正常等待、单守异常均有反向用例。
- 质量：全量测试、20 房边界、UI audit、隔离 preflight、另起实例和 CI 通过。
- 独立验收：核心黑盒与官方 UI 对照两组双盲，未产出报告不计通过。

## 7. 已踩坑与防复发

1. **启动 id 笔误**：`startWatcher(state.watchers[id])` 在 `for (const entry …)` 中让全部守失效；必须使用当前 entry，并由调度器统一挂载。
2. **ack 后漏评**：issue 守 `watch_ack` 是终态，后续 PR 评论不再唤醒；评审/返工必须开 `watch_pr_start` 走独立评论水位。
3. **正常等待误报停摆**：`pollHealth` 先判正常等待再判故障，不能只看 lastPoll 年龄。
4. **内存错误假可见**：只改局部 `entry.lastError`，`readState` 仍为空；错误必须 persist 后通过公开视图重读。
5. **optional 校验假绿**：required 不能按 actual 过滤；optional 才可按出现与否参与比较。
6. **投影分裂**：client、statusView、调度器各自判 enabled/poll，导致一处异常、一处主理中；必须统一事实源。
7. **CRLF 假回归**：Windows checkout 会让 LF 硬编码源码探针批量失败；先验证 blob/换行，再判断产品回归。
8. **会话 scope 假象**：URL 带 `sessionId` 不等于服务端已过滤；必须检查实际 watcher/Ticket 列表与写保护。
9. **独立实例误解**：官方独立部署不是脱离 DSH，而是与日常 profile 分离；本项目选择项目会话制，不照搬独立 Router。
10. **房间数量假象**：20 个房间不自动等于优雅；巨型 `lib/index.js`、巨型 UMD client 与重复镜像仍需收口。
